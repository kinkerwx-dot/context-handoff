# Context Handoff

跨聊天交接、继续任务和查看进度的本地 Codex Skill。

**当前版本：v1.3.5 · 试用版（Pre-release）**

它整理让接收端能够继续工作的最小可靠上下文，保留必要证据、关键决策原因和权限边界。它不能找回不可访问的聊天，也不会把历史授权自动转移到新聊天。

## 使用

- “交给 Codex”或“交给 ChatGPT”：生成一段可复制交接正文。
- “接着做”：核验必要资料后，在当前授权内实际继续任务。
- “看看进度”：区分已验证进展、未完成事项和下一步。

自然语言自动选择取决于宿主环境。如需明确选择，使用 `$context-handoff` 并说明任务。该入口也不代表执行权限扩大。

## 本地安装

需要已安装并可使用本地 Skill 的 Codex。首次安装可执行：

```sh
git clone https://github.com/kinkerwx-dot/context-handoff.git "$HOME/.agents/skills/context-handoff"
```

如果该目录已经存在，请先比较现有版本，不要覆盖本机改动。安装后在 Codex 中使用 `$context-handoff`；若未被发现，重新启动宿主并检查其 Skill 配置。

仓库根目录包含 `SKILL.md`，`agents/openai.yaml` 提供界面元数据。无需额外脚本或第三方运行依赖。

## 跨环境与剪贴板

Mac 本机路径不能作为云端唯一证据。交接正文应内联下一步必需且可安全分享的资料，或引用已确认接收端可访问的来源。

剪贴板写入是可选便利功能：只有当前环境确实支持且获准使用时才尝试。不可用或失败时保留清晰可复制的正文，不宣称已复制。准备交接或复制不代表已发送、已收到或接收端已完成任务。

不读取原有剪贴板，不复制凭据等敏感内容，不为复制扩权、安装工具或开启新服务。发送和实际执行仍须符合当前用户授权。

## 验证与限制

截至 2026-10-28，在一个本地 Mac/Codex 与 ChatGPT 账号环境中观察到：

- 原生读取当前 Skill 正文；自然语言自动选择并非每次都有加载证据。
- 浏览器剪贴板写入并实际粘贴成功；同环境的 shell 剪贴板命令失败。
- 真实 ChatGPT 接收交接后完成短任务，反向交接后 Codex 实际执行内存断言。
- 冷启动账目核验：识别重复和作废记录，实际算出总额170，未沿用无证据的旧值。
- 编辑交接、冲突进度核验和工时分析均有原生会话测试；工时分析实际算出3.5并通过断言。

以上主要是受控、虚构数据测试，不是长期生产可靠性、所有模型或所有平台的保证。尚没有固定自动化回归套件。某些测试使用显式调用和指定解释器，不能把结果推广为默认环境必然成功。

测试中还观察到 ChatGPT 网页无法显示部分回复，尽管聊天读取接口可取得正文。该显示故障未修复，不能宣称全界面端到端通过。首次内存执行曾触发被拒绝的启动器缓存写入，换用独立解释器后重测通过；不将失败尝试隐去或计为零违规。
